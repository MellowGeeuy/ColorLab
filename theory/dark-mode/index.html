ตอนที่ 09 · การเข้าถึง

Dark Mode ที่ทำถูกวิธี

ธีมมืดไม่ใช่การกลับสีทั้งหน้า แต่ต้องออกแบบชุดสีใหม่ที่มีกฎของตัวเอง กดปุ่มรูปพระจันทร์มุมขวาบนเพื่อดูหน้านี้แบบธีมมืดได้เลย

01

ทำไมต้องรู้เรื่องนี้

เส้นทางที่ทีมส่วนใหญ่เดินซ้ำกันคือแบบนี้

สัปดาห์แรก

ผู้ใช้ขอธีมมืด ทีมกลับสีทั้งหน้าด้วย filter หรือสลับ token สองสามตัว ได้ผลลัพธ์ที่ดูใช้ได้ในสกรีนช็อตแรก

สัปดาห์ถัดมา

เริ่มมีรายงานว่าปุ่มหาไม่เจอ เงาหายไปหมดจนไม่รู้ว่าอะไรอยู่บนอะไร และอ่านนาน ๆ แล้วตาล้ากว่าธีมสว่างอีก

สามอาการนี้มาจากกฎสามข้อที่ธีมมืดมีแต่ธีมสว่างไม่มี

02

หลักการ

03

ยกระดับความสูงด้วยตัวเอง

ในธีมสว่าง เราบอกว่าอะไรลอยอยู่เหนืออะไรด้วยเงา แต่ในธีมมืดเงาแทบไม่มีผล เพราะเงาคือการทำให้มืดลง และพื้นก็มืดอยู่แล้ว ธีมมืดจึงใช้วิธีตรงข้าม คือทำให้พื้นผิวที่อยู่สูงกว่าสว่างขึ้นทีละนิด

ลองยกระดับความสูง ลากเพื่อเปลี่ยนระดับ
กล่องแจ้งเตือน

ยกระดับแล้วพื้นผิวสว่างขึ้น ไม่ใช่เงาเข้มขึ้น

ระดับ 2

ขาวทับ · สีพื้นผิว · ตัวหนังสือ

สังเกตว่าพอยกสูงขึ้น คอนทราสต์ของตัวหนังสือจะค่อย ๆ ลดลง เพราะพื้นสว่างเข้าหาตัวหนังสือ นี่คือเหตุผลที่ธีมมืดมีเพดานของความสูง ไม่ใช่ยกไปได้เรื่อย ๆ

04

ข้อผิดที่เจอบ่อย

  • ใช้ดำสนิทกับขาวล้วน คอนทราสต์ 21:1 ทำให้เกิดแสงฟุ้งรอบตัวหนังสือ อ่านนานแล้วตาล้า ใช้เทาเข้มกับเทาอ่อนแทน
  • ยกสีแบรนด์ให้สว่างขึ้นแล้วลืมตัวหนังสือบนปุ่ม พอพื้นปุ่มสว่างขึ้น ตัวหนังสือสีขาวจะตกเกณฑ์ ต้องพลิกเป็นสีเข้มพร้อมกัน
  • ใช้เงาบอกความสูงเหมือนธีมสว่าง เงาบนพื้นมืดแทบไม่เห็น ให้ใช้พื้นผิวที่สว่างขึ้นแทน
  • ใช้สี semantic ชุดเดิมจากธีมสว่าง แดงและเขียวระดับ 600 มักตกเกณฑ์บนพื้นเข้ม ต้องมีชุดของธีมมืดแยกต่างหาก
05

สรุปและแหล่งอ้างอิง

สรุปสามข้อ

  • ธีมมืดคือชุดสีอีกชุด ไม่ใช่การกลับค่าของชุดเดิม
  • ความสูงบอกด้วยพื้นผิวที่สว่างขึ้น ไม่ใช่เงาที่เข้มขึ้น
  • สีแบรนด์และ token คู่ของมันต้องถูกออกแบบใหม่สำหรับพื้นมืด

อ่านต่อจากต้นทาง

  • Material Design · Dark themeที่มาของแนวทาง elevation overlay และการลดความสดในธีมมืด
  • WCAG 2.2 · SC 1.4.3เกณฑ์เดียวกันนี้ใช้กับธีมมืดด้วย และต้องวัดแยก
