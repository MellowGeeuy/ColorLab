ตอนที่ 03 · พื้นฐาน

Color Models เลือกให้ถูกงาน

HSL ปรับง่ายก็จริง แต่มีจุดอ่อนสำคัญอยู่ข้อหนึ่ง คือตั้งค่าความสว่างเท่ากัน แต่ตาไม่ได้เห็นว่าสว่างเท่ากัน OKLCH ทำขึ้นมาเพื่อแก้เรื่องนี้โดยเฉพาะ

01

ทำไมต้องรู้เรื่องนี้

อาการที่ทำให้คนเจอเรื่องนี้ครั้งแรกมักเป็นสองอย่างนี้

อาการที่ 1 · ไล่สีแล้วขุ่นกลางทาง

ไล่จากน้ำเงินไปเหลือง แต่ช่วงกลางกลายเป็นเทาสกปรก ทั้งที่สองปลายสวยดี

อาการที่ 2 · สเกลที่มีขั้นโดด

สร้างสเกล 11 ขั้นด้วยการลดความสว่างทีละเท่า ๆ กัน แต่พอวางเรียงแล้วมีบางขั้นกระโดด ทั้งที่ตัวเลขห่างเท่ากันเป๊ะ

ทั้งสองอาการมาจากรากเดียวกัน คือโมเดลสีที่ใช้อยู่คิดเลขในปริภูมิที่ไม่ตรงกับการมองเห็น

02

หลักการ

โมเดลเด่นที่ข้อจำกัด
HEXสั้น คัดลอกง่าย รองรับทุกที่อ่านแล้วเดาไม่ออกว่าสีอะไร
RGBตรงกับวิธีที่จอแสดงผล รองรับ alphaไม่สอดคล้องกับการรับรู้ของสายตา
HSLปรับทีละแกนได้ เหมาะกับสร้างสเกลความสว่างเท่ากันแต่ตาเห็นไม่เท่ากัน
OKLCHความสว่างตรงกับที่ตาเห็นจริง ไล่เฉดไม่ขุ่นเบราว์เซอร์เก่ามากต้องมี fallback
ตั้งความสว่างเท่ากัน แล้วลองวัดดู ลากเปลี่ยนเนื้อสี
240°
HSL — ตั้ง Lightness ไว้ 55% ตลอด

ความสว่างที่ตาเห็น

OKLCH — ตั้ง Lightness ไว้ 62% ตลอด

ความสว่างที่ตาเห็น

ลากจนครบวงจะได้ช่วงนี้ — ฝั่ง HSL อยู่ระหว่าง 8.6% ถึง 75.1% ต่างกัน 8.8 เท่า ส่วน OKLCH อยู่ระหว่าง 22.2% ถึง 25.5% ต่างกันแค่ 1.15 เท่า ทั้งที่สองฝั่งตั้งค่าความสว่างไว้ค่าเดียว ไม่ได้ขยับเลย

03

เขียน OKLCH ยังไงให้เบราว์เซอร์เก่าไม่พัง

OKLCH ใช้ได้ในเบราว์เซอร์หลักทุกตัวแล้ว แต่ถ้าต้องรองรับเครื่องเก่า วิธีที่ปลอดภัยที่สุดคือเขียนค่าเดิมไว้ก่อน แล้วค่อยทับด้วย @supports

อีกเรื่องที่ OKLCH เปิดให้ทำได้คือสีนอกขอบเขต sRGB จอสมัยใหม่หลายรุ่นแสดง Display P3 ได้ ซึ่งกว้างกว่า sRGB ราว 50% แต่ต้องระวังว่าสีที่หลุดขอบเขต จะถูกเบราว์เซอร์ดึงกลับเข้ามาเอง และความสว่างอาจเพี้ยนไปจากที่ตั้งไว้

04

ข้อผิดที่เจอบ่อย

  • ใช้ HSL สร้างสเกลแล้วเชื่อตัวเลข Lightness สีเหลืองกับสีน้ำเงินที่ L เท่ากันให้ความสว่างที่ตาเห็นต่างกันเกือบ 9 เท่า ต้องวัดคอนทราสต์เสมอ
  • ไล่สีใน sRGB แล้วได้ช่วงกลางขุ่น ใช้ in oklch หรือ in oklab ใน gradient เพื่อให้ช่วงกลางไม่ตกลงไปทางเทา
  • เขียน oklch ทับ hex ผิดลำดับ ค่า fallback ต้องอยู่ก่อน ไม่งั้นเบราว์เซอร์ใหม่จะได้ค่าเก่าแทน
  • ใช้ HEX เป็นแหล่งความจริงของระบบสี HEX แก้ทีละนิดไม่ได้ ถ้าต้องสร้างสเกลหรือปรับทั้งชุด ให้เก็บเป็น HSL หรือ OKLCH แล้วค่อยแปลง
05

สรุปและแหล่งอ้างอิง

สรุปสามข้อ

  • HEX และ RGB เหมาะกับการเก็บและส่งค่า แต่แก้ทีละนิดไม่ได้
  • HSL เหมาะกับการปรับทีละแกน แต่ตัวเลขความสว่างไม่ตรงกับที่ตาเห็น
  • OKLCH ให้ความสว่างที่ตรงกับการรับรู้จริง เหมาะที่สุดกับการสร้างสเกล

อ่านต่อจากต้นทาง

  • CSS Color Module Level 4สเปกที่นิยาม oklch() lch() และการไล่สีข้ามปริภูมิ
  • Oklab color spaceที่มาของ Oklab และเหตุผลที่ออกแบบให้เท่ากันเชิงการรับรู้
  • OKLCH in CSS — Evil Martiansบทความที่อธิบายข้อดีเชิงปฏิบัติพร้อมตัวอย่างจริง
